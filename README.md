# LIMO

Code and data release accompanying the paper LIMO. 



LIMO executes a **semantic filter** over a document collection, i.e., a yes/no
predicate applied to every document, using a cheap **small LLM** and escalating
to an expensive **large LLM** only when needed. Every escalation is treated as a
learning opportunity rather than a one-off cost:

- disagreements between the two models are distilled into reusable textual
  **experiences** that are replayed in-context to the small model (Section 4);
- a learned **experience utility estimator**  selects which
  experiences to inject, and a learned **router** decides when to
  escalate; both are updated **online** from execution feedback (Section 5);
- an offline **corpus warm-start** (contrastive query synthesis + cost-aware
  active labeling) bootstraps the learned modules on a fresh corpus with no
  historical queries (Section 6).

As more data is processed, the small model handles increasingly many cases on
its own and large-model calls steadily decrease.


> 📦 **The benchmark datasets are bundled in this repository** no external
> download required. All three datasets (CUAD, Policy, Cancer) are under
> **[`datasets/`](datasets/)** · details in [`datasets/README.md`](datasets/README.md).

> 💡 **Example experiences.** The experiences generated by one run of each config are
  bundled under [`examples/experiences/`](examples/experiences/): `opp115.jsonl` (Policy),
  `hoc.jsonl` (Cancer), `cuad.jsonl` (one experience per line). So you can read what the
  method produces without running it.

> 💬 **Prompts.** All prompts the method uses live in the code, organized by stage:
  the small/large answering prompts and experience injection in
  [`pipeline/common/prompts.py`](pipeline/common/prompts.py); the experience-generation
  prompts (small-model explanation + large-model synthesis) in
  [`pipeline/experience_generator/prompts.py`](pipeline/experience_generator/prompts.py);
  and the offline query-synthesis prompts in
  [`pipeline/query_synth/doc_contrastive.py`](pipeline/query_synth/doc_contrastive.py).

| Path | Contents                                                                                                                                                                                                                                     |
|---|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `pipeline/` | The LIMO framework. Each subpackage is one swappable stage with a `REGISTRY` + `build()` factory.                                                                                                                                            |

### Inside `pipeline/`

| Subpackage | Role                                                                                                                                                    | Paper |
|---|---------------------------------------------------------------------------------------------------------------------------------------------------------|---|
| `runner/` | Streaming executor: routes each point, calls small/large, triggers online updates and experience generation.                                            | Section 3 |
| `experience_generator/` | Turns an escalated disagreement into a corrective experience (small-model self-explanation → large-model synthesis), with a cost-aware generation gate. | Section 4 |
| `experience_retriever/` | Experience utility estimator / selector. `care_pq` (default) is a Bayesian-logistic-regression reranker.                                                | Section 5.3 |
| `router/` | Escalation decision. `lightgbm` (default) is a learned agreement-score head; `confidence_threshold`, `automix`, `all_small`, `all_big` are baselines.   | Section 5.4 |
| `query_synth/` | Offline contrastive query synthesis for the warm-start.                                                                                                 | Section 6.1 |
| `label_synth/` | Offline cost-aware active labeling + joint warm-start of the router and utility estimator.                                                              | Section 6.2 |
| `trainer/` | Offline training of the router / experience retriever.                                                                                                  | Section 6 |
| `fewshot_retriever/` | Optional plain few-shot demonstration retriever (disabled in the main method).                                                                          | — |
| `common/` | Shared dataclasses, prompt builders, confidence extraction, embedding client, large-prediction cache, etc.                                              | — |

## Installation

Requires Python ≥ 3.10. Core dependencies:

```bash
pip install "numpy>=1.24" "pandas>=2.0" "scikit-learn>=1.3" "scipy>=1.10" \
            "openai>=1.0" "PyYAML>=6.0" "requests>=2.28"
```

Optional extras:

- **Local model serving** (the bundled embedding server): `sentence-transformers`, `fastapi`, `uvicorn`, `torch`, `transformers`.
- **Some `tools/` baselines**: `litellm` (TaskCascade upstream adapter); ScaleDoc/Stretto pull in `torch` / `transformers` / `scipy`.

## Model endpoints

LIMO talks to three services over HTTP (OpenAI-compatible chat completions for
the LLMs, a small `/embed` endpoint for the retriever). They are configured
through environment variables (or per-run config overrides):

| Variable | Default | Meaning |
|---|---|---|
| `MOP_SMALL_URL` / `MOP_SMALL_MODEL` | `http://localhost:8105/v1` · `Qwen3.5-0.8B` | Small model endpoint + served name |
| `MOP_LARGE_URL` / `MOP_LARGE_MODEL` | `http://localhost:8102/v1` · `Meta-Llama-3.1-70B-Instruct` | Large model endpoint + served name |
| `MOP_EMBED_URL` | `http://localhost:8200/embed` | Sentence-embedding endpoint |

## Datasets

Three real-world semantic-filtering benchmarks (paper Table 2), **bundled in
this repository under [`datasets/`](datasets/)** (see
[`datasets/README.md`](datasets/README.md)) — no external download needed:

| Paper name | Config key | Domain | #Docs | #Queries | Avg. tokens |
|------------|---|---|---|---|---|
| **CUAD**   | `cuad` | Legal contracts (CUAD) | 482 | 38 | 3,288 |
| **Policy** | `opp115` | Privacy policies (OPP-115) | 3,273 | 9 | 88 |
| **Cancer** | `hoc` | Cancer abstracts (Hallmarks of Cancer) | 1,852 | 10 | 331 |

Throughout the paper these datasets are called **CUAD**, **Policy**, and
**Cancer**; the `Config key` column is the identifier used in code and configs
(`data.dataset`).

Each dataset declares its document table, text column, and a
`(document, query, ground_truth)` pairs file in `eval/data.py`. Ground-truth
labels are used **only** for offline scoring and are never observed during execution.

## Setting experiment parameters

An experiment is fully described by a single **YAML (or JSON) config** loaded by:

```bash
python -m eval --config path/to/config.yaml
```

The schema is defined in [`eval/config.py`](eval/config.py). It has **one section
per pipeline stage**, so any component can be swapped without touching code. A
stage is chosen by a registry `name` plus a free-form `kwargs` dict forwarded to
that stage's constructor. Individual fields can also be overridden on the command
line with `--set section.field=value`.

### Config sections

| Section | Key fields | Notes |
|---|---|---|
| `data` | `dataset`, `queries` | `dataset ∈ {cuad, opp115, hoc}`; `queries` accepts `all_eval`  / a comma-separated list. |
| `experience_pool` | `source` | `empty`, a bundled name, or a JSONL path. |
| `experience_retr` | `name`, `kwargs` | Experience utility estimator. `name ∈ {care_pq, care, topk_semantic_online, topk_semantic}`. |
| `experience_gen` | `name`, `kwargs` | Online experience generation. `name = online_discrepancy`; omit to disable. |
| `fewshot_retr` | `name`, `kwargs` | Plain few-shot demos. `name ∈ {topk_semantic, topk_semantic_large_only}`; `k: 0` disables. |
| `router` | `name`, `kwargs` | Escalation policy. `name ∈ {lightgbm, confidence_threshold, automix, all_small, all_big}`. |
| `pretrain` | `mode`, `router_checkpoint`, `retriever_snapshot` | `none` / `load` (use pretrained artifacts) / `fit` (run the Section 6 warm-start first). |
| `llms` | `small_prompt_mode`, `large_prediction_cache`, endpoints | Endpoints default from the env vars above. |
| `runner` | `workers`, `gen_workers`, `frozen` | `frozen: true` disables all online updates (evaluate a fixed pretrained system). |
| `reporting` | `output` | Path for the results JSON (required). |

### Key hyperparameters of the full method

| Where | Parameter | Meaning | Paper |
|---|---|---|---|
| `experience_retr` (`care_pq`) | `k` | Number of experiences injected into the small-model prompt (default 8). | Section 5.3 |
| | `blend_lambda` | Per-query ↔ global head shrinkage strength (default 20). | Section 5.3 |
| `experience_gen` (`online_discrepancy`) | `max_per_query` | Cap on experiences generated per query. | Section 4.2 |
| | `position_gate_rho` | Cost-aware generation gate `ρ = c_gen /(β·c_L)`; a trigger at position `t` fires only if `t ≤ n_q /(1+ρ)`. Omit to disable the gate. | Section 4.2 |
| `router` (`lightgbm`) | `threshold` | Escalate when the predicted small=large agreement probability falls below this. | Section 5.4 |
| | `refit_every` | Router refit cadence, counted in processed data points. | Section 7.1 |
| | `use_care_features` | Include the mean-pooled experience features + mean utility in the router input. | Section 5.4 |

### Example: the full LIMO cell

An annotated configuration that runs the complete method — learned router +
`care_pq` selector + online experience generation, warm-started from pretrained
artifacts:

```yaml
data:
  dataset: opp115
  queries: all_eval
  within_query_order: doc_id_asc
  order_seed: 0

experience_pool:
  source: empty                 # the online generator fills the pool

experience_retr:
  name: care_pq
  kwargs:
    k: 8                        # experiences injected per point
    blend_lambda: 20.0          # per-query vs global shrinkage

experience_gen:
  name: online_discrepancy
  kwargs:
    max_per_query: 50
    # position_gate_rho: 6.42   # optional cost-aware generation gate

fewshot_retr:
  name: topk_semantic
  kwargs:
    k: 0                        # few-shot disabled; experiences are the mechanism

router:
  name: lightgbm
  kwargs:
    threshold: 0.5              # escalate below this agreement probability
    refit_every: 500            # refit cadence in processed data points
    use_care_features: true

pretrain:
  mode: load                    # load pretrained router + utility estimator
  router_checkpoint: path/to/router_lgbm.pkl
  retriever_snapshot: path/to/care_snapshot.json

llms:
  small_prompt_mode: 3way
  large_prediction_cache:
    - examples/predictions/zeroshot_all_queries/Llama-3.1-70B-Instruct_zeroshot_opp115.csv

runner:
  workers: 8

reporting:
  output: results/limo_opp115.json
```

Swapping `router.name` to `confidence_threshold` (with
`experience_gen`/`experience_retr` removed) recovers the `Confidence` baseline;
`all_small` / `all_big` give the small-only / large-only anchors.

## Reproducing the main experiment

The main cost-at-accuracy-target experiment (method = `Ours`) ships as one
ready-to-run config per dataset under `configs/main/`, each pinned to its
selected operating point:

| Paper name | Config | Run |
|---|---|---|
| **Policy** | `configs/main/opp115.yaml` | `scripts/run_main.sh opp115` |
| **Cancer** | `configs/main/hoc.yaml`    | `scripts/run_main.sh hoc`    |
| **CUAD**   | `configs/main/cuad.yaml`   | `scripts/run_main.sh cuad`   |




```bash
# 1. bring up the small + large + embedding endpoints (see "Model endpoints")
# 2. run one dataset end-to-end (warm-start pretraining -> evaluation):
scripts/run_main.sh cuad          # CUAD
scripts/run_main.sh opp115        # Policy
scripts/run_main.sh hoc           # Cancer
```

Note:

- **`pretrain.mode: fit` needs the live small and large models.** Query synthesis
  and cost-aware active labeling issue real model calls. The warm-start writes its artifacts to
  `runs/pretrain/<dataset>/` and is resumable.

## Some Naming notes

- In the code the method is registered internally as **`Ours`**; the paper name
  is **LIMO**.
- `mpq` in configs = `max_per_query` (max experiences generated per query).
- `care_pq` is the experience utility estimator / selector; the router named
  `confidence_threshold` is the paper's `Confidence` baseline; the router named
  `lightgbm` is the paper's learned router (a calibrated gradient-boosted
  decision tree; the default backend is scikit-learn's
  `HistGradientBoostingClassifier`).
